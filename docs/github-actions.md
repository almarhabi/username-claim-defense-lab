# تشغيل المختبر وبوت Telegram عبر GitHub Actions

## الحد المهم

GitHub-hosted runners مؤقتة، ومهمة Actions ليست بديلاً عن خادم يعمل باستمرار. لذلك يستخدم المشروع مسارين مختلفين:

- **tests:** بناء واختبار تلقائي على GitHub-hosted runner، بلا رموز بوت وباتصال بالمختبر فقط.
- **synthetic-lab-controller:** تشغيل يدوي على Self-hosted runner تملكه. تبدأ المهمة الحاويات ثم تنتهي، بينما تبقى الحاويات تعمل بسياسة `restart: unless-stopped` ما دام الجهاز وDocker يعملان.

لا تشغّل workflow يحتوي أسراراً على Self-hosted runner في مستودع عام أو مع مساهمين غير موثوقين.

## 1. تجهيز الجهاز المستمر

ثبّت Docker وDocker Compose على جهاز المختبر، ثم سجّل Self-hosted runner خاصاً بهذا المستودع من:

`Settings > Actions > Runners > New self-hosted runner`

شغّل خدمة الـrunner وفق تعليمات GitHub. يجب أن يكون مستخدم الـrunner قادراً على تنفيذ أوامر Docker. لا تمنحه صلاحيات أوسع من اللازم، ولا تستخدم جهازاً يحتوي بيانات إنتاج.

## 2. إضافة الأسرار

افتح:

`Settings > Secrets and variables > Actions > New repository secret`

أضف الأسماء الثلاثة التالية كما هي:

| Secret | القيمة |
|---|---|
| `TELEGRAM_BOT_TOKEN` | رمز البوت الذي يتحكم في المختبر فقط |
| `TELEGRAM_ALLOWED_USERS` | معرفات Telegram الرقمية المسموح لها، مفصولة بفواصل |
| `LAB_ADMIN_KEY` | مفتاح عشوائي طويل خاص بإدارة المختبر |

مثال شكل قائمة المستخدمين، وليس قيمة يجب نسخها:

```text
123456789,987654321
```

لا تضع الأسرار في `.env.example` أو في YAML أو في رسائل Commit. ملف البيئة الفعلي مستبعد من Git، والـworkflow يكتب ملف التشغيل بصلاحيات المالك فقط ويحذفه عند انتهاء المهمة.

## 3. بدء الخدمة

من تبويب **Actions** اختر **synthetic-lab-controller** ثم **Run workflow**:

- `up`: بناء الصور وتشغيل الخادم والبوت، مع الاحتفاظ بقاعدة البيانات.
- `restart`: إعادة تشغيل الحاويات مع الاحتفاظ بقاعدة البيانات.
- `status`: عرض حالة الحاويات.
- `down`: إيقاف الحاويات دون حذف وحدة تخزين قاعدة البيانات.

بعد نجاح `up` تنتهي مهمة Actions، وهذا متعمد؛ استمرار الخدمة يكون عبر Docker لا عبر إبقاء الـjob معلقاً. عند إعادة تشغيل الجهاز يجب أن تكون خدمة Docker مفعّلة حتى تعيد الحاويات ذات سياسة `unless-stopped` تشغيل نفسها.

## 4. التحقق

أرسل `/help` ثم `/status` من حساب Telegram موجود في القائمة البيضاء. يجب أن يظهر:

- `lab_only: true`
- `domain: social.lab.internal`

لإنشاء جلسة داخل المختبر استخدم `/session alice`. لا ترسل كلمة مرور في Telegram، ولن يعرض البوت رمز الجلسة في المحادثة.

## الاختبار المؤقت على GitHub-hosted

يمكن تشغيل **tests** يدوياً من Actions. يبني هذا المسار خادم المحاكاة ويتحقق من `/health` ثم يحذف الحاويات ووحدة التخزين المؤقتة. لا يحتاج إلى Telegram token ولا يبدأ بوتاً حقيقياً.
